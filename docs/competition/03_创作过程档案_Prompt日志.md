# 创作过程档案：Prompt 与人机协作迭代日志

- **项目名称**：番茄计划（Pomodoro Planner）
- **在线网址**：https://chenyanzou.github.io/pomodoro-planner/
- **开源仓库**：https://github.com/chenyanzou/pomodoro-planner
- **协作方式**：采用「结构化需求访谈（`/grill-me`）→ 方案权衡与设计文档定稿 → 独立审阅查漏 → 三阶段测试驱动迭代（`v0.1` → `v0.3` → `v1.0`）→ 浏览器实测与全库审查修复 → 自动化上线」的完整工程化 AI 协作工作流。

## Prompt 协作过程全记录（四栏标准档案）

| 阶段 | 使用工具 | 我的 Prompt（原始输入 / 关键决策指令） | AI 返回结果 | 我做的人工改动 / 审核决策 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 需求立项与架构访谈** | Antigravity（`/grill-me` 模式） | `/grill-me 目前我需要你为我开发一个部署在GitHub上的网站项目所有人都可以访问（你操作我的GitHub新建一个公有仓库），我想要一个番茄钟计划安排表可以记录和删改自己的目标安排。前端也要有优化` | AI 先检查本地开发环境（Node v24、Git、无 `gh` CLI），随后按设计树逐一发起 8 轮结构化访谈，依次澄清数据存储架构、界面交互形态、计时器功能、统计复盘、视觉美学、前端跨端优化、GitHub 建仓方式与仓库命名。 | 我在 8 轮访谈中逐一拍板核心产品方向：① 选定**纯前端本地持久化 + JSON 导入导出**以完美适配 GitHub Pages 免登录访问；② 选定**专注区 + 今日计划表 + 目标拆解视图**三联动形态；③ 选定**可定制番茄钟 + Web Audio 白噪音 + 全屏沉浸模式**；④ 选定**轻量复盘看板（7/30 天趋势、占比环图、热力图、可删改流水）**；⑤ 选定**暖纸极简 × 浅/深双主题**；⑥ 选定**简体中文 + 响应式 + PWA 离线 + 全局快捷键**；⑦ 选定**内置浏览器协助建仓**。 |
| **2. 补充比赛交付规范** | Antigravity | 在确认仓库名为 `pomodoro-planner` 时补充明确比赛提交需求：`同时开发完成后交给我一份压缩包除了包含核心项目材料还包含提交代码仓库链接（如GitHub、Gitee）或各迭代版本文件（v0.1、v0.3、v1.0，体现修改过程）；提交一页功能说明，写清这个网页是干什么的、有哪些按钮和功能、怎么使用。（3）创作过程档案：须同步提交 Prompt 日志，内容包括“使用工具—我的 Prompt—AI 返回结果—我做的人工改动”四项。（这我们学校的一个AI使用比赛）` | AI 将比赛要求完整纳入项目规格，回放全部需求并提出 3 套技术栈对比方案（方案 A：React 19 + TS + Vite + Tailwind + 自定义轻量 SVG 图表 + PWA；方案 B：引入 Recharts/dnd-kit 重型组件库；方案 C：零构建原生 JS）。 | 我审核 3 套技术方案的体积与可维护性权衡后，最终拍板**方案 A**（放弃重型图表库以最大化首屏加载优化，同时保障工程化演进质量）。 |
| **3. 设计文档撰写与独立审阅定稿** | Antigravity（`brainstorming` + 独立 Builder 审阅子代理） | 在 AI 产出设计文档并经独立审阅代理反馈迭代节奏问题后，我先确认采用**连贯三阶段真实迭代推进（`v0.1 → v0.3 → v1.0`）**，随后审阅完整设计文档并回复：`确认通过` | AI 输出完整设计文档 `docs/design.md`（明确数据 Schema、单事实来源契约、暖纸双主题色板、独立仓库与交付目录边界），并经独立审阅补充了防冲突契约。 | 我复核了 AI 提出的 4 项工程默认决策（`FocusSession[]` 作为复盘唯一事实来源、开源仓库与比赛打包目录物理分离、Vite `base` 弹性路径、首次访问中文演示数据引导）后正式签字通过。 |
| **4. 实施计划审核与执行方式选定** | Antigravity（`writing-plans` 技能） | 审阅 12 步详细实施计划后确认：`计划没问题，采用 Native 模式直接开始连贯开发（完成后做整库独立审查）` | AI 生成包含 5 项高风险 Review Focus 边界测试的 12 任务实施计划（涵盖 TDD 红绿循环、Git 里程碑标签与浏览器验收）。 | 我审阅任务拆分与里程碑划分（Task 1–4 对应 `v0.1`、Task 5–8 对应 `v0.3`、Task 9–12 对应 `v1.0` 与打包），选定连贯 Native 执行 + 末期全库独立审阅的最高效策略。 |
| **5. `v0.1` MVP 迭代构建** | Antigravity + Vite / React / Vitest | 按已批准计划自动推进 `v0.1` 里程碑（Task 1–4） | AI 初始化独立 Git 仓库 `pomodoro-planner`，以 TDD 方式完成本地时区日期工具与基于 `endTimestamp` 的防漂移计时引擎（9 项单测）、版本化存储与分离式上下文（12 项单测），实现 `v0.1` 番茄钟与今日基础任务 CRUD 界面，构建通过并打 `v0.1` 标签与导出源码快照。 | 依据我的前期产品决策，验收确保无外部字体阻塞、构建产物轻量化（`v0.1` ~82 KB gzip）且任务删除不影响历史专注记录。 |
| **6. `v0.3` 完整排程、目标拆解与统计复盘迭代** | Antigravity + Vitest | 按已批准计划自动推进 `v0.3` 里程碑（Task 5–8） | AI 升级完整日排程（日期导航、四时段分组、优先级、拖拽排序、未完成顺延、编辑弹窗、5 秒撤销提示），新增「目标拆解」视图与一键生成任务联动，以 TDD 实现统计聚合与严格 JSON 备份校验（18 项单测全绿），实现 `React.lazy` 懒加载 SVG 复盘看板（独立拆包仅 5.9 KB gzip），打 `v0.3` 标签并导出快照。 | 严格落实「不引入 ECharts 等数百 KB 重型图表库」的前端优化要求，所有趋势柱状图、分类环图与 12 周热力图均采用纯轻量 SVG 组件实现。 |
| **7. `v1.0` 前端精修、浏览器实测与独立代码审查修复** | Antigravity + 内置浏览器 QA 代理 + 独立高级代码审阅代理 | 按已批准计划完成 `v1.0` 功能与上线前双轨实测（Task 9–10） | AI 实现 Web Audio 纯合成提示音与 3 种白噪音、全屏沉浸模式、全局快捷键、移动端底部导航、自定义番茄 SVG 图标、PWA 离线预缓存与 GitHub Actions 自动部署流水线。随后在真实浏览器 QA 与独立代码审阅中**暴露并定位出多处真实缺陷**：① React 19 `setState` 批处理导致删除任务 5 秒撤销 Toast 未弹出；② `TimerContext` 渲染期跨上下文更新且每秒触发任务列表重渲染；③ 向下拖拽排序缺陷与移动端 `390px` 视口横向溢出（482px）；④ 深色模式次级文字对比度偏低；⑤ 首次未手势解锁 AudioContext 导致提示音静默；⑥ 弹窗与按钮聚焦时快捷键误触。AI 针对性补写 TDD 回归测试（扩充至 22/22 全绿）并一次性全部修复，经浏览器二次实测验证：撤销恢复正常、深色模式清晰、390px 移动端横向溢出为 `0px`。 | 我在立项阶段明确要求“前端也要有优化”并坚持完成浏览器实测与独立审查，促使 AI 在发布前真实发现并彻底修复了 React 19 批处理撤销失效、移动端布局溢出和深色对比度问题（而非停留在“编译通过即交差”）。 |
| **8. GitHub 建仓、自动化部署与比赛材料打包** | Antigravity + 内置浏览器 + Git / GitHub Actions | 在内置浏览器跳转 GitHub 登录页后，我亲自完成账号登录并回复：`已登录` | AI 在已登录标签页中自动创建公开仓库 `chenyanzou/pomodoro-planner`，通过 SSH 推送 `main` 分支与 `v0.1`/`v0.3`/`v1.0` 全部标签，配置 GitHub Pages（GitHub Actions 源）触发自动构建，实地打开 `https://chenyanzou.github.io/pomodoro-planner/` 核验线上运行正常。 | 我亲自把控账号安全登录授权（不向 AI 暴露密码或 Token），实地打开线上网址检查实际访客体验。 |
| **9. 真实体验后的人工产品修正（`v1.0.1` 演示模式隔离改造）** | Antigravity + Vitest + GitHub Actions | 亲自体验线上页面后提出真实改进指令：`目前所有人进入都有你加入的演示数据但是肯定别人用肯定不需要这些数据你把这些统合加入一个演示按钮吧在小月亮旁边点一下进入演示，正常进去没有啥数据。最后项目的前端还是太丑了你昨晚工作后出一份交接文档我交给其他AI做前端优化` | AI 按 TDD 先更新存储测试（验证默认启动为空白工作区），将 `AppDataContext` 拆分为持久化 `realState` 与内存隔离 `demoState`，在顶栏小月亮旁新增「演示 / 退出演示」按钮与演示状态提示条（体验演示绝不覆盖个人本地数据），22/22 测试通过后提交 `v1.0.1` 并推送自动更新线上网站，同时输出前端深度视觉重设计交接文档。 | **关键人工产品拍板**：发现“默认展示假数据对真实用户有侵入感”的体验缺陷，主动要求改为默认纯净空态 + 显式可切换的演示入口，并计划在下一阶段引入其他 AI 专项升级前端视觉美学。 |
